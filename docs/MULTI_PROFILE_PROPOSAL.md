# Несколько входов VLESS/Reality: предложение для 0.2.0

Статус: согласовано пользователем командой «делай», реализовано в 0.2.0. Перечень выполненных и оставшихся испытаний — в TESTING.md. Документ сохраняет обоснование выбранного поведения.

## Рекомендуемое поведение

Каждый серверный inbound хранится в клиенте как отдельный профиль VLESS/Reality: адрес, порт, UUID, SNI, публичный ключ, Short ID и flow. Несколько портов одного сервера допустимы. Пользователь добавляет каждый профиль вручную или из буфера.

Экран «Серверы» содержит список с названием, выбранным профилем, результатом последней проверки, задержкой в миллисекундах и временем проверки. Действия: «Добавить», «Изменить», «Проверить», «Использовать». Проверки выполняются через соответствующий VLESS/Reality outbound, а не только открытием TCP-порта. До проверки — «Не проверен»; отсутствие свежего результата не означает подтверждённый отказ.

По умолчанию выбор ручной. Переключение во время работы явно предупреждает о возможном разрыве текущих соединений; выбор приложений сохраняется. Подтверждение активного профиля приходит от ядра, а не от одного нажатия кнопки.

## Автоматический выбор как отдельная опция

Режим «Авто по задержке» использует sing-box URLTest. Он оценивает доступность контрольного HTTPS-адреса через каждый профиль и задержку, выбирает подходящий доступный профиль, а при отказе может перейти к другому при следующей проверке. Это не измерение максимальной скорости загрузки.

Предварительные параметры: проверка раз в минуту, допуск по задержке 100 мс для уменьшения частых переключений. В журнал записываются реальный выбранный профиль, смена выбора и результаты проверок. Если ни один профиль не отвечает, показать проблему и продолжать ограниченные проверки; не выбирать direct как резервный outbound.

Не обещать мгновенное переключение: отказ замечается после проверки, а текущие TCP/UDP сессии не переносятся без разрыва. Несколько inbound на одном сервере не защищают от падения самого сервера или его сети.

Проверки могут обращаться к внешнему контрольному HTTPS-адресу и расходуют небольшой объём трафика. Значение «78 мс» показывать как задержку, не как скорость. Полный замер Мбит/с возможен отдельным действием позднее, поскольку расходует существенно больше данных.

## Android-уведомление

Один постоянный foreground-service notification: «Sme11_VPN · VPN включён», активный профиль, загрузка и отдача, кнопка «Отключить». Скорость берётся из реальных счётчиков ядра и обновляется примерно раз в секунду в native service, включая работу при свёрнутом Flutter UI.

Пример: «Вход 443 · ↓ 840 кбит/с · ↑ 96 кбит/с». Пересчёт: байт/с × 8 / 1000. При больших значениях использовать Мбит/с. Нулевой трафик показывать как 0, а не считать отказом VPN.

Текущий SDK уже обновляет уведомление в фоне, но форматирует байт/с; в приложении также отсутствует runtime-запрос POST_NOTIFICATIONS. Для Android 13+ добавить запрос при действии пользователя. Отказ не должен препятствовать VPN. Нужна поддерживаемая локальная модификация SDK для нужного текста и единиц, без ручных правок глобального pub-cache.

## Хранение и совместимость

Новый каталог профилей хранится целиком в защищённом хранилище под отдельным версионированным ключом. Старый `vless_profile_v1` читается как единственный профиль при первом переходе. Старый ключ сохраняется, запись нового каталога проверяется до использования. Идентификатор профиля локальный и независим от UUID VLESS, поскольку разные inbound могут использовать одинаковый UUID.

Проверки доступности не сохраняются как вечный статус. Секреты всех профилей маскируются в журнале. Повреждённый новый каталог не перезаписывается молча. Откат и ошибка записи не должны приводить к потере старого профиля.

## Реализация и проверки

1. Каталог профилей, безопасное чтение старого формата, тесты отказа записи и выбора активного профиля.
2. Группа selector с сохранением Android allowlist и Windows process_path; ручной выбор и реальные результаты URLTest.
3. Отдельная настройка автоматического URLTest, если согласована; проверка отказа одного профиля и всех профилей.
4. Android-разрешение уведомлений и native-формат скорости; проверка включения, сворачивания, блокировки экрана, отказа в разрешении и остановки через уведомление.
5. Проверки конфигурации официальным ядром, автоматические тесты, Android APK. Windows требует сборочного окружения Visual Studio; готовый EXE не обещать без сборки.

Источники: [Selector](https://sing-box.sagernet.org/configuration/outbound/selector/), [URLTest](https://sing-box.sagernet.org/configuration/outbound/urltest/), [разрешение уведомлений Android](https://developer.android.com/develop/ui/compose/notifications/notification-permission). Возможности Android SDK сверены с исходниками закреплённого flutter_singbox_client 1.1.0.
