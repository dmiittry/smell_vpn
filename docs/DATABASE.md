# Хранение данных

SQL-базы и сервера хранения нет. В 0.2.0 реализован перенос одного профиля в защищённый каталог.

| Данные | Место | Формат |
| --- | --- | --- |
| Каталог VLESS/Reality | flutter_secure_storage | JSON v2, ключ `profiles_v2`, профили, локальные ID, выбранный ID, automatic |
| Старый профиль | flutter_secure_storage | `vless_profile_v1`, сохраняется после переноса |
| Результаты HTTPS-проверок | Память | Задержка/ошибка и время; не сохраняются как вечная доступность |
| Выбранные приложения | SharedPreferences | JSON `apps_v1` |
| Режим маршрутизации | SharedPreferences | `all_apps`, по умолчанию false |
| Диагностика | SharedPreferences | `diagnostic`, по умолчанию false |
| Журнал | Каталог данных приложения | `events-v1.json`, 500 важных / 1000 сетевых / 300 подробных; необязательный ID записи |
| Служебный Android-журнал | filesDir, AtomicFile | `vpn-runtime-events.json`, 150 lifecycle/сеть/питание/завершение процесса + 50 сводок ядра; ID и время |

Android защищает профиль средствами платформенного хранилища плагина; резервное копирование приложения отключено. Windows использует защищённое хранилище плагина для текущего пользователя. Секретный профиль не сохраняется в SharedPreferences.

Журнал не шифруется. Маскирование убирает UUID, VLESS URI, ключи и известные параметры профиля, но адреса соединений и домены могут присутствовать. Экспорт выполняется только по действию пользователя.

Служебный журнал не содержит конфигурации, адресов сервера, UUID, ключей, description/tombstone Android или произвольного текста ошибок ядра. Он сохраняет фиксированные сообщения и коды причин. Старый events-v1.json читается в прежнем формате списка, ID необязателен; удаления профилей и миграции защищённого каталога нет.

При отсутствии `profiles_v2` старый профиль читается, проверяется и записывается в новый каталог. Повторное чтение должно совпасть с записанным JSON до использования. Старый ключ не удаляется. Повреждённый новый каталог не подменяется старым молча: запись блокируется, причина попадает в журнал. Локальные ID независимы от UUID: разные inbound могут использовать один UUID. Каталог ограничен 20 профилями.

Порт и секрет локального API случайны для каждого запуска, существуют только в памяти и конфигурации native service. В каталог, журнал и SharedPreferences они не записываются.
