# Sme11_VPN 0.2.1 — диагностика отключений

## Результат

Из журналов POCO от 6 и 8 октября нельзя установить причину отключения: отсутствуют события остановки процесса/сервиса. В экспорте от 8 октября ровно 1000 записей, без ERROR/WARN; видны повторная инициализация и новый запуск. Это не доказывает блокировку системой, отказ сервера или crash ядра.

Исправлены подтверждённые недостатки приложения:

- CommandClient больше не объявляет сервис остановленным при потере управляющего сокета. Три попытки восстанавливают только управление, не весь VPN. Поздние callbacks старого клиента игнорируются.
- Повторные EventChannel-подписки отменяют прежние collectors; соседние одинаковые INFO/DEBUG дополнительно объединяются в пределах 100 мс.
- Старый onLost и фоновые обновления интерфейса не сбрасывают уже выбранную новую физическую сеть.
- ERROR отдельного соединения попадает в журнал без ложного баннера отказа запуска работающего VPN.
- Основной журнал сохраняет независимо 500 важных, 1000 сетевых, 300 подробных событий. При выключенной подробной диагностике TRACE/DEBUG от ядра отбрасываются. Важные события инициируют запись сразу, медленная запись объединяет изменения без неограниченной очереди.
- Отдельный AtomicFile-журнал Android работает при закрытом UI: 150 lifecycle/сеть/питание/завершение процесса и 50 безопасных сводок ошибок ядра. Android 11+ добавляет доступные ApplicationExitInfo с исходными временем и кодами. Произвольные crash dumps, секреты и конфигурации не сохраняются. Служебные записи импортируются с ID без дублей.
- Штатный запрос остановки отличается от неожиданного; STOPPED подтверждается после освобождения сервиса. Пустой sticky-перезапуск не имитирует восстановление VPN. Подключение после уничтожения процесса остаётся ручным.

## Проверки

Статический анализ без замечаний, 30 Flutter-тестов прошли. Нативные JVM-тесты скорости, Android-кодов и безопасной классификации ошибок прошли через `:flutter_singbox_client:testDebugUnitTest`. Итоговые APK собраны для arm64-v8a, armeabi-v7a и x86_64.

Android 16 эмулятор использует сохранённый синтетический профиль 192.0.2.1:443. Его запуск подтверждает только работу TUN, сервиса, интерфейса и диагностики. Реальное VLESS/Reality-соединение, доступность сервера и стабильность POCO этим не проверены.

## Установка и ограничения

Для POCO: `dist/Sme11_VPN-0.2.1-arm64-v8a.apk`. Перед обновлением отключить VPN; установить поверх предыдущей версии, не удаляя приложение. Контрольные суммы — `dist/SHA256-0.2.1.txt`.

Итоговый arm64 APK: versionName 0.2.1, versionCode 2004, minSdk 24, targetSdk 36; размер 84 443 745 байт. SHA-256: `1c7ae23b4a51b9cd87562c68c5fd835ccee10bbab7209c72e1ba45cea25f29eb`. Сертификат совпадает с 0.2.0: SHA-256 `597fd345947e2a228e16dbb8b63c007cf72e14f1b60da40d79b365f43c8bc491`. Итоговый x86_64 APK повторно установлен и запущен в эмуляторе после последней сборки.

Android-ядро 1.14.0-alpha.20 оставлено без изменений; Windows EXE не собран. Подпись по-прежнему тестовая, сборка предназначена для личного использования. Kill switch отсутствует: после остановки VPN выбранные приложения могут использовать обычную сеть.

Нельзя обещать, что HyperOS больше не завершит процесс. Новая диагностика должна помочь отличить завершение процесса, отзыв VPN, потерю сети и ошибку управления. Android может вернуть неполную или неизвестную причину. При следующем сбое экспортировать «Все» события, включая источник Android.

Проверка эмулятора 0.2.1: штатный NotificationStopReceiver остановил сервис без ложного баннера; ServiceRecord исчез, native-журнал сохранил запрос, освобождение ресурсов, onDestroy и подтверждённый STOPPED. При force-stop работающего тестового приложения следующая инициализация добавила ApplicationExitInfo с кодом 10 и исходным временем. Дубли native-ID в сохранённом основном журнале отсутствовали. Снимок прошлых причин содержит историю процесса, включая обновления пакета; старые записи нельзя трактовать как причину текущего сбоя.
