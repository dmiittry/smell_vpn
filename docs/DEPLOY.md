# Сборка и распространение

## Исходники 0.3.0

```powershell
git clone https://github.com/dmiittry/smell_vpn.git
cd smell_vpn
```

Включён оригинальный `vendor/flutter_singbox_client/android/libs/libbox.aar` (около 91 МиБ), SHA-256 — в DEPENDENCIES.md. Его не требуется искать в локальном Pub-кэше. Пути `android/local.properties` создаются Flutter на компьютере сборки. Ключи подписи и пользовательские настройки не входят в репозиторий.

Новые локальные сборки имеют версию 0.3.0+5; имена и ограничения — в [RELEASE_0.3.0.md](RELEASE_0.3.0.md). Для воспроизведения Android-сборки требуется собственный локальный debug-ключ либо настроенная release-подпись; чужая подпись не позволит установить APK поверх существующего приложения.

## Android

0.2.1: исправления диагностики и состояния VPN. Для POCO — `dist/Sme11_VPN-0.2.1-arm64-v8a.apk`, контрольные суммы — `dist/SHA256-0.2.1.txt`. Устанавливать поверх предыдущей версии без удаления данных, предварительно отключив VPN. Android-ядро остаётся прежним.

Требуются Flutter 3.47.5, Android SDK и JDK из Android Studio. Текущий шаблон использует AGP 9.1.0 / Gradle 9.3.1 с совместимостью для плагинов на Kotlin Gradle Plugin; отключать предупреждение о будущей миграции не нужно.

```powershell
.\scripts\build_android.ps1
# Если Flutter не добавлен в PATH:
.\scripts\build_android.ps1 -Flutter C:\flutter\bin\flutter.bat
```

Скрипт отключает Windows-платформу только для своего процесса, затем выполняет успешный `pub get`, анализ, тесты и сборку. Это позволяет собрать Android на Windows без Developer Mode и Visual Studio. Нельзя игнорировать ошибку `pub get`: без созданного `GeneratedPluginRegistrant.java` APK может собраться, но упасть при запуске JNI и не зарегистрировать VPN-плагин.

APK находятся в `build/app/outputs/flutter-apk`. Для современных телефонов обычно нужен `app-arm64-v8a-release.apk`.

В первой версии release подписывается локальным debug-ключом шаблона. Это сборка для личного тестирования. Перед публикацией настроить отдельный keystore, исключить секреты подписи из Git и согласовать канал распространения.

0.2.0: arm64 APK для POCO — `dist/Sme11_VPN-0.2.0-arm64-v8a.apk`, суммы — `dist/SHA256-0.2.0.txt`. Подпись совпадает с 0.1.1; устанавливать поверх предыдущей версии, без удаления приложения. Старый профиль переносится автоматически. Перед установкой отключить работающий VPN.

После первого переноса SDK из Pub-кэша старый Kotlin incremental cache может ссылаться на прежний путь. Исправление без удаления файлов: из `android` выполнить `./gradlew.bat :flutter_singbox_client:compileReleaseKotlin '-Pkotlin.incremental=false' --rerun-tasks`, затем повторить обычную сборку. В PowerShell аргумент с точкой заключать в кавычки.

## Windows x64

На 2026-10-21 Windows x64 версия 0.2.1 собрана. Готовы установщик `dist/Sme11_VPN-0.2.1-Windows-x64-Setup.exe` и переносимый архив `dist/Sme11_VPN-0.2.1-Windows-x64-Portable.zip`. Контрольные суммы — `dist/SHA256-Windows-0.2.1.txt`.

Для повторной сборки нужны Flutter, Visual Studio Build Tools 2022 с MSVC/CMake/Windows SDK и Inno Setup 6. В этой среде проверенные официальные инструменты подготовлены в `.tools`; Build Tools зарегистрирован в системе. Удалять его следует через Visual Studio Installer. Developer Mode не включался: локальные ссылки зависимостей создаются как junction.

```powershell
.\scripts\prepare_windows.ps1
.\scripts\build_windows.ps1
```

Скрипт не запускает скачанные установщики, не меняет сеть и не устанавливает службы. SHA-256 проверяется по официальным метаданным закреплённого GitHub Release. Для обновления версии ядра требуется заново проверить конфигурацию и маршрутизацию.

Передать всю папку `build/windows/x64/runner/Release`; запускать `sme11_vpn.exe` от имени администратора для создания TUN. Приложение само не повышает права и не создаёт постоянную службу.

Установщик содержит всю папку Release, ядро, лицензии и app-local Visual C++ Runtime. Устанавливается для текущего пользователя в `%LOCALAPPDATA%/Programs/Sme11_VPN` и создаёт пункт меню «Пуск». Ярлык рабочего стола необязателен. Обновление не удаляет профили и журнал в пользовательском каталоге данных. Portable ZIP нужно полностью распаковать; один EXE без соседних DLL и data/core не работает. Runtime не требует установки Visual Studio на другом ПК.

Созданный установщик установлен и проверен: завершение 0, установленный EXE совпадает со сборкой по SHA-256, упакованное ядро запускается. Ранее собранная программа открывалась и отображала главный экран и журнал без ошибок. Финальная дополнительная UI-проверка установленной копии остановлена пользователем клавишей Escape. Реальное VLESS/Reality-подключение не проверялось, сетевые маршруты ПК не менялись.
