# Архитектура

## Отображение соединения в 0.3.0

TunnelState отражает жизненный цикл сервиса. Независимое поле `connectionCheck` в AppController хранит результат HTTPS-пробы активного outbound текущей сессии. `connectionVerified` требует running, совпадения тега, успешного и свежего результата (до 90 секунд). До ответа статус нейтральный; после ошибки проверки красный, но сервис не останавливается. Ошибки запуска выводятся из lastError только в failed.

Проверка начинается после готовности локального управления и определения фактического сервера, повторяется после смены тега, вручную и раз в минуту при активном интерфейсе. Ревизия проверки инвалидируется при переключении, остановке и dispose. Старые ответы не обновляют текущий статус. Карта health остаётся отдельной историей проверок списка серверов.

## Слои

- `lib/domain`: профиль, строгий разбор VLESS, модель маршрутизации, построение sing-box JSON, уровни логов и маскирование.
- `lib/services`: защищённый каталог, интерфейс VPN-ядра и локальный CoreControl.
- `lib/app_controller.dart`: состояние приложения, команды, обработка событий и ограниченный журнал.
- `lib/ui`: адаптивные экраны Material 3 и форма профиля.
- `android`: канал получения приложений; системный VPN управляется готовым адаптером sing-box.
- `windows`: Flutter runner, канал привязки процесса к Job Object, упаковка официального ядра.

## Подключение

1. Проверка полей профиля и непустого списка приложений.
2. Построение JSON из типизированного профиля.
3. Проверка JSON самим sing-box.
4. Android: проверка наличия пакетов и системное согласие на VPN. Windows: запуск отдельного процесса.
5. Состояние running приходит от ядра; UI не имитирует подключение таймером.
6. Ошибки ядра маскируются и записываются; неожиданная остановка сохраняет причину на главном экране.

В Android в allowlist включается собственный пакет клиента как страховка: удаление выбранных приложений не должно превратить список в пустой и захватить трафик всех программ. Сокеты ядра защищаются от повторного попадания в VPN адаптером.

Windows конфигурация передаётся через stdin, без временных файлов с ключами. Job Object с `KILL_ON_JOB_CLOSE` завершает ядро при закрытии runner. Копия EXE запускается без оболочки и без интерполяции пользовательских данных в команды.

## DNS и диагностика

Адрес самого сервера разрешается системным DNS. Android и режим «Все» используют DoH через proxy для DNS внутри туннеля. Windows в режиме выбранных EXE сохраняет системный DNS, поскольку служба DNS Client не принадлежит выбранному приложению.

Журнал имеет независимые квоты: 500 важных, 1000 обычных сетевых и 300 диагностических записей; сообщения ограничены 1800 символами. Обычные записи сохраняются каждые 600 мс, важные инициируют запись сразу. Одновременно записывается один снимок; при изменениях следующий снимок содержит актуальные данные, очередь устаревших копий не растёт. Незавершённая запись при аварии может потеряться.

Android дополнительно ведёт атомарный служебный журнал независимо от Flutter: 150 событий lifecycle/сети/питания/завершения процесса и 50 безопасных сводок ошибок ядра. Повтор одинаковой сводки ограничен одним разом в 30 секунд. Профиль и произвольные тексты исключений в него не передаются. UI читает записи при запуске, остановке и раз в пять секунд; исходные время и ID исключают повторный импорт. Android 11+ предоставляет ApplicationExitInfo, но причина относится ко всему процессу и может быть неполной.

Состояние VPN меняется по lifecycle сервиса и подтверждённому запуску ядра. Потеря CommandClient записывается как проблема управления, запускает максимум три восстановления, не закрывает туннель и не объявляет его остановленным. Каждая новая подписка EventChannel отменяет предыдущий collector. Старые callbacks клиента и физической сети не должны изменять новый сеанс. Отдельные ERROR ядра не считаются отказом всего VPN.

Без конфигурации сервис не восстанавливается после завершения процесса: используется START_NOT_STICKY, повторный Intent работающего сервиса не создаёт второе ядро. Секретная конфигурация на диск не записывается. Остановка подтверждается после освобождения ресурсов и onDestroy. «VPN включён» означает работающий локальный туннель, а не доказанную доступность удалённого сервера.

## Каталог и переключение 0.2.0

`ProfileCatalog` содержит до 20 `SavedProfile`, выбранный локальный ID и признак automatic. Все правила VPN направлены в стабильный selector `proxy`; изменение сервера не меняет Android allowlist или Windows process_path. Selector выбирает профиль либо URLTest `auto`. Группа auto содержит только VLESS outbounds, без direct. URLTest выполняет HTTPS-пробу раз в минуту с допуском 100 мс. При переключении существующие соединения могут закрываться.

`ControlledVpnEngine` управляет запуском, локальным API и проверками. Офлайн-проверка запускает ядро без inbound/TUN и подавляет события временного сервиса, чтобы UI не показывал VPN включённым. При работающем VPN проверки используют уже запущенное ядро. Ошибки отдельных проб записываются как предупреждения и не становятся сообщением о невозможности запуска VPN.

Android SDK хранится в `vendor/flutter_singbox_client`. Native service обновляет уведомление из собственных событий статистики, независимо от Flutter UI. Байты/с умножаются на 8 и делятся на 1000 для кбит/с. Активный профиль берётся из групп ядра, общий state не имитируется. Менеджер работающего сервиса переживает закрытие Activity; повторно открытый UI получает реквизиты собственного локального API через MethodChannel.
