## 2026-10-29 — удаление профилей и проверяемый автовыбор

По запросу пользователя добавлено удаление неработающего профиля, включая запущенный VPN: после подтверждения сначала останавливается ядро, затем сохраняется каталог. Автоматика не включается без свежей проверки и подтверждения доступного тега. Выключение auto сохраняет фактический сервер. Нулевая задержка не означает доступность. Фоновый URLTest и версии ядер сохранены. Подробности — [RELEASE_0.3.1.md](RELEASE_0.3.1.md).

## 2026-10-22 — минимальный интерфейс и достоверный пинг

Пользователь запросил оформление по примерам Hiddify и публикацию в новом репозитории. Сохранены собственные знак щита/питания и четыре функциональных раздела: VPN, серверы, приложения, логи. Удалены рекламные надписи и лишние карточки. Логотипы и изображения Hiddify не включены.

Запуск TUN и доступность сервера различаются: зелёный статус появляется только после HTTPS-пробы конкретного активного outbound; рядом всегда показана измеренная задержка. Внутреннее состояние сервиса остаётся running при неудачной пробе, чтобы ошибочный результат не разрывал рабочие соединения. На экране в таком случае красный статус и ошибка; кнопку можно использовать для отключения.

Каждая смена активного сервера/сессии сбрасывает подтверждение. Асинхронные результаты относятся к ревизии проверки и не могут подтвердить другое соединение. Пробы выполняются через существующий локальный API ядра; в фоне интерфейс не добавляет минутных проверок. HTTPS-доступность не гарантирует маршрутизацию любого приложения или доступность всех сайтов.

Пустой публичный репозиторий dmiittry/smell_vpn используется без изменения его видимости. Исходники адаптера, лицензии и оригинальный libbox.aar сохраняются; SDK, кэши, сборки и локальные настройки исключены из Git. Существующие версии ядра, механизм хранения профилей и сетевые правила не изменяются.

## 2026-10-15 — достоверность состояния и сохранение причин остановки

Пользователь поручил исправить журналы и определение состояния VPN. Журналы POCO не позволяли установить причину: после повторного запуска сохранялись только сетевые сообщения, без lifecycle и Android-причин завершения.

Потеря управляющего сокета не является доказательством остановки VPN. Состояние изменяется только жизненным циклом сервиса; восстанавливается канал управления, а не весь туннель. Три попытки ограничивают нагрузку. Запрос пользователя и неожиданная остановка различаются.

Сетевой шум не должен вытеснять важную историю: используются независимые квоты и дополнительный атомарный native-журнал. В native-журнал попадают фиксированные сообщения и безопасные категории ошибок, без секретных текстов. ApplicationExitInfo помогает различить crash, нехватку памяти и другие причины, но не гарантирует точную диагностику HyperOS.

START_STICKY с пустым Intent не восстанавливал конфигурацию и мог создавать ложные попытки запуска. Используется START_NOT_STICKY; хранение секретной конфигурации и автоматическое восстановление уничтоженного процесса не добавлялись. Ядро и серверные настройки не менялись: их виновность журналом не установлена.

## 2026-10-06 — несколько серверов и уведомление 0.2.0

Пользователь согласовал предложенное расширение командой «делай». Каждый inbound — отдельный защищённый профиль с собственным локальным ID: UUID VLESS может совпадать. Миграция не удаляет старый ключ и проверяет новую запись повторным чтением; повреждённый каталог не перезаписывается молча.

Ручной выбор включён по умолчанию. Необязательный URLTest использует задержку HTTPS-пробы, не обещает максимальную пропускную способность. Интервал 1 минута и допуск 100 мс уменьшают частые переключения. Серверы на одном хосте не защищают от отказа всего хоста. Все VPN-правила остаются направлены в selector proxy; auto не включает direct. Это не kill switch при остановке самого сервиса.

Для одинакового управления Android/Windows используется локальный Clash API sing-box с случайным портом и Bearer-токеном. Он привязан только к loopback и не публикуется в сети. При холодном открытии Android Activity реквизиты берутся из своего работающего native VPN service, без записи в постоянные файлы.

SDK закреплён как локальная модификация flutter_singbox_client 1.1.0. Это позволяет поддерживать уведомление и менеджер сервиса без правок pub-cache. Нативные счётчики уведомления продолжают работать при закрытии Activity; скорость — байты/с × 8 / 1000. Отказ POST_NOTIFICATIONS не блокирует VPN.

## 2026-10-06 — исправление диагностики 0.1.1

Журнал пользователя с POCO содержит 546 строк INFO/DEBUG/TRACE, ошибочно экспортированных как ERROR, и ни одной текстовой ERROR/FATAL/PANIC записи. Уровень обычного события определяется по заголовку sing-box; при отсутствии заголовка сохраняется уровень адаптера. Fault/state-события не понижаются. Старые записи ядра переклассифицируются с сохранением содержимого и времени, без изменения формата хранилища. Поиск слова ERROR в теле не применяется, чтобы DNS NOERROR и цитаты не создавали ложных ошибок.

Пользователь сначала сообщил об отсутствии интернета, затем проверил и уточнил, что VPN работает и интернет есть. Скриншот показал работающий туннель и ложный баннер «VPN не удалось запустить». Параметры сети и профиля для этого исправления не меняются. Проверка обновлённого APK непосредственно на POCO остаётся за пользователем: устройство не подключено к среде разработки.

## 2026-10-06

### Собственный Flutter-интерфейс вместо форка Hiddify

Причина: пользователю нужен собственный минимальный продукт. Лицензия Hiddify содержит дополнительные требования к форку, коммерческому использованию и похожему интерфейсу. Код и ресурсы Hiddify не переносились. Общий принцип простоты сохранён.

### Готовое ядро sing-box

Причина: не писать собственную реализацию VPN-протокола. Android использует готовый адаптер `flutter_singbox_client`, Windows — официальный CLI. Минус: разные версии ядра; Android-плагин включает alpha, что требует отдельной проверки перед публичным выпуском.

### Только VLESS/Reality TCP

Причина: пользователь использует VLESS/Reality и не использует WireGuard. Ограниченный набор проще проверить. Другие транспорты явно отклоняются; расширение требует отдельного тестирования.

### Выбранные приложения по умолчанию

Причина: главное требование пользователя. Пустой список блокирует запуск. Android использует allowlist; Windows — правила по полному пути процесса с direct по умолчанию. Изменения требуют отключения VPN.

### Системный DNS в Windows при выбранных EXE

Причина: запросы обычного приложения может выполнять отдельная системная служба DNS. Глобальная отправка DNS через VPN меняла бы поведение невыбранных приложений. Ограничение явно показано пользователю; полноценная изоляция DNS требует дополнительных решений.

### Хранение и диагностика

Профиль хранится в защищённом хранилище. Логи маскируются до сохранения, ограничены 1000 событиями и экспортируются по инициативе пользователя. В Windows профиль передаётся через stdin, поэтому временный открытый JSON не нужен.

### Нет автоматического подключения и kill switch в первой версии

Причина: начало и окончание VPN должны быть явными. После разрыва возможен обычный сетевой доступ выбранных приложений. Изменять это поведение без согласования нельзя.

### Отдельный сценарий сборки Android

Проверка release APK обнаружила отсутствие GeneratedPluginRegistrant после прерванного `pub get` из-за Windows symlink. Скрипт `build_android.ps1` временно задаёт `FLUTTER_WINDOWS=false`, проверяет успешное завершение настройки и наличие регистратора до сборки. Системные настройки безопасности не меняются, регистрация плагинов остаётся штатной Flutter.
