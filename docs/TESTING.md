## Интерфейс 0.3.0 — 2026-10-22

Все 37 Flutter-тестов прошли. Проверены ширины 320, 390, 1180; форма профиля и навигация; отсутствие зелёного статуса до HTTPS-ответа; пинг при успехе; красный цвет, ошибка и возможность отключения при неудачной пробе. Для POCO скопирован arm64 APK; подпись совпадает с 0.2.1, Android package `com.sme11.sme11_vpn`, версия 0.3.0, versionCode 2005, targetSdk 36. Контрольные суммы сохранены в dist.

Тестовый профиль использует зарезервированный адрес `192.0.2.1` и синтетический ключ. Команда `check` проверяет конфигурацию, но не создаёт рабочее соединение с VPN-сервером.

`dart scripts/check_multi_core.dart third_party/windows/core/sing-box.exe` запускает настоящий API без TUN. Проверены 401 без токена, HTTPS-проба, отказ недоступного пути, подтверждение ручного выбора и автовыбор доступного пути. Тест использует direct/socks fixture, HTTPS gstatic и локальную HTTP-страницу для URLTest; это проверка управления, не Reality. Отказ HTTPS-пробы проверяется недоступным локальным HTTPS-адресом. Полный отказ реальных VLESS-профилей остаётся ручным испытанием.

## Ручная проверка перед выпуском

1. Импорт своего VLESS/Reality профиля и ручное заполнение тех же параметров дают одинаковое подключение.
2. Отказ в разрешении Android не показывает running.
3. Выбранный браузер видит выходной IP VPN; невыбранный — IP обычной сети. Проверить IPv4, IPv6 и UDP.
4. Удалённый пакет и пустой выбор не запускают VPN для всех.
5. Изменение режима во время работающего туннеля недоступно.
6. Смена Wi-Fi/LTE, потеря сети, остановка сервера и отключение через системное уведомление отражаются в журнале.
7. Некорректные SNI/ключ/Short ID дают ошибку Reality; соединение не считается здоровым по одному запуску TUN.
8. Экспорт учитывает фильтр/поиск и содержит русский UTF-8 текст без UUID и ключей.
9. Windows: проверить отдельные дочерние EXE, DNS, остановку ядра при закрытии и аварии UI, восстановление маршрутов.
10. Два реальных профиля: проверка каждого, ручное переключение активного VPN, отказ текущего профиля в Auto и отказ всех. Проверить отсутствие direct fallback для выбранных приложений и обычную сеть у остальных.
11. Android: отказ уведомлений не блокирует VPN; проверить ненулевую скорость, блокировку экрана, HyperOS/POCO, повторное открытие Activity и остановку через уведомление.

Реальный сервер в этой сессии не предоставлен. End-to-end проверка подключения, скорости, IPv6/DNS и split tunneling с реальным сервером остаётся обязательной.

Проверка эмулятора 0.2.1: штатный NotificationStopReceiver остановил сервис без ложного баннера; ServiceRecord исчез, native-журнал сохранил запрос, освобождение ресурсов, onDestroy и подтверждённый STOPPED. При force-stop работающего тестового приложения следующая инициализация добавила ApplicationExitInfo с кодом 10 и исходным временем. Дубли native-ID в сохранённом основном журнале отсутствовали. Снимок прошлых причин содержит историю процесса, включая обновления пакета; старые записи нельзя трактовать как причину текущего сбоя.
